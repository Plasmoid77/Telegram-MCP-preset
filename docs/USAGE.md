# Использование и эксплуатация

## Владельцу: что можно просить

Всё делается в личке с ботом или обращением к нему в разрешённой группе.

- **Поручения по Telegram:** «что нового в <группе>», «ответь X, что…», «найди сообщение про…»,
  «вступи в группу по ссылке…». Большие задачи тоже, например «сделай путеводитель по топику
  <тема> и выложи туда».
- **Группы:**
  - добавить — «разрешаю тебе писать в <группе>», «включи <группу>», «можешь общаться в <группе>»;
  - убрать — «не пиши в <группе>», «выключи <группу>»;
  - узнать список — «в каких группах ты отвечаешь?».
  
  Бот должен состоять в группе. Изменение действует в течение минуты.
- **Память:** «запомни…», «впредь…», «больше не…» — бот дописывает правило в `memory.md` и
  говорит, что записал. «Забудь…» или «исправь в памяти…» — правит запись.
- **Подтверждения:** перед необратимым (удаление, выход из групп, блокировки, рассылки, профиль)
  бот переспрашивает, если вы не сказали явно.
- **Секретарь:** когда чужому человеку нужен владелец, бот присылает сводку в `NOTIFY_CHAT`.

## Режимы

| Режим | Кто | Что доступно |
|---|---|---|
| `owner` | `OWNER_ID`, в личке или в группе | все инструменты `mcp__telegram__*`; `Read` — только сохранённые большие результаты, `FILES_DIR` и `memory.md`; `Edit`/`Write` — только `memory.md`. Лимиты `OWNER_*`. В группе поручения принимаются только из сообщений владельца |
| `guest` | все остальные | 17 инструментов: чтение текущего чата, ответ, реакция, «печатает», прочитано, пересылка владельцу, просмотр медиа. `guard.py` не пускает в другие чаты. Файлов, папок и памяти нет |

## Как обрабатывается сообщение

**Личка.**

1. Сервер ждёт ~6 с тишины и пишет в ленту одну строку на «пачку» сообщений.
2. Диспетчер читает новые строки с сохранённого смещения и склеивает пачки одного чата.
   Отбрасывает строки старше `MAX_AGE` и свои собственные.
3. Проверяет лимиты и запускает агента: `owner`, если чат — `OWNER_ID`, иначе `guest`.

Смещение сохраняется **до** запуска. Если диспетчер упадёт посреди ответа, сообщение будет
пропущено, а не отвечено дважды.

**Группы.** Лента групп не видит, поэтому диспетчер сам опрашивает `wait_for_events` по HTTP.

1. Разрешённые группы — чаты, явно добавленные в папку `GROUPS_FOLDER`, плюс `GROUPS`. Папка
   перечитывается раз в 60 с.
2. Пачка закрывается после 5 с тишины или через 30 с от первого сообщения.
3. Диспетчер сам, без агента и бесплатно, читает тексты и оставляет обращённые к боту:
   - reply на его сообщение или @упоминание (флаг Telegram `addressed`);
   - слово из `GROUP_TRIGGERS` целым словом без учёта регистра («Думбот,» — да; «роботы» — нет).
4. Сообщения владельца идут в запуск `owner`, остальных — в отдельный `guest`. Ответ уходит
   reply-ем на обращение и попадает в ту же тему форума.

## config.env

Перечитывается на каждой итерации, перезапуск не нужен.

| Ключ | Пример | Смысл |
|---|---|---|
| `OWNER_ID` | `123456789` | id владельца, включает режим owner |
| `OWNER_NAME`, `OWNER_USERNAME` | `Иван`, `@ivan` | подставляются в промпт |
| `SELF_ID` | `987654321` | id аккаунта-бота; его сообщения игнорируются |
| `ACCOUNT_NAME`, `BOT_NAME` | `Proxy`, `Нейросетевой Doom bot` | подставляются в промпт |
| `NOTIFY_CHAT` | = `OWNER_ID` | куда слать уведомления секретаря; `me` — «Избранное» бота |
| `MODEL` | `claude-sonnet-5-5` | модель |
| `MAX_TURNS` / `RUN_TIMEOUT` | 15 / 300 | шаги и секунды на запуск гостя |
| `OWNER_MAX_TURNS` / `OWNER_RUN_TIMEOUT` | 40 / 900 | то же для владельца |
| `OWNER_MCP_OUTPUT_TOKENS` | 150000 | `MAX_MCP_OUTPUT_TOKENS` для owner-запусков (по умолчанию в Claude Code — 25000) |
| `PER_CHAT_PER_HOUR` / `TOTAL_PER_HOUR` | 20 / 80 | лимиты запусков против флуда |
| `MAX_AGE` | 1800 | пачки ленты старше этого (с) пропускаются |
| `GROUPS_FOLDER` | `Doom: группы` | папка Telegram со списком групп; пусто — не использовать |
| `GROUPS` | `-100…` | группы вручную, через запятую |
| `GROUP_TRIGGERS` | `Думбот,Джарвис,бот` | слова-обращения |
| `FILES_DIR` | `~/TelegramMCP` | должен совпадать с `TELEGRAM_ALLOWED_ROOTS` сервера |
| `CLAUDE_BIN` | — | путь к `claude`, если не найден сам |

**Константы в `dispatcher.py`:**

- `GROUP_SETTLE = 5`, `GROUP_MAX_WAIT = 30`, `FOLDER_REFRESH = 60` (с);
- `MEMORY_MAX = 8000` (символов);
- `GUEST_TOOLS`. Если добавляете инструмент, у которого chat-аргумент называется иначе, чем
  `chat_id`, `user_id`, `from_chat_id` или `to_chat_id`, допишите проверку в `guard.py`.

**Когда применяются изменения:**

- `dispatcher.py` — после `systemctl --user restart telegram-agent`;
- `prompt.md`, `memory.md`, `config.env`, хуки и `settings.json` — со следующего запуска бота.

## Команды

```bash
systemctl --user status telegram-mcp telegram-agent
journalctl --user -u telegram-agent -f
journalctl --user -u telegram-mcp -f
tail -f ~/.local/state/telegram-mcp/incoming_feed.jsonl     # лента лички
cat ~/.local/share/telegram-agent/memory.md                 # память бота

# идёт ли сейчас запуск бота (проверяйте перед перезапуском диспетчера)
pgrep -af "^$HOME/.local/bin/claude -p" | cut -c1-120

systemctl --user disable --now telegram-agent   # выключить автоответчик (MCP работает дальше)
systemctl --user enable --now telegram-agent
```

**Перед перезапуском `telegram-agent` дождитесь конца текущего запуска.** Перезапуск убивает
идущий запуск бота: он в том же cgroup. Сообщение тогда останется без ответа.

## Журнал telegram-agent

| Строка | Значит |
|---|---|
| `chat=<id> tier=owner\|guest rc=0 error=False subtype=success turns=N Ts` | ответ выполнен. Пишется по **завершении** запуска. Отрицательный id — группа |
| `groups folder '<имя>': [...]` | изменился список групп |
| `groups folder read error (keeping [...])` | папку прочитать не удалось, работает прежний список |
| `group poll error: ...` | MCP недоступен. Личка работает дальше, повтор через 5 с |
| `group events: server restarted, continuing from now` | перезапускался сервер |
| `rate limit: skip ...` | сработал лимит |
| `skip stale burst` | пачка старше `MAX_AGE` |
| `TIMEOUT`, `non-json output`, `rc≠0` | проблема с агентом: логин, лимиты подписки или таймаут |

## Диагностика

| Симптом | Что проверить |
|---|---|
| Не отвечает в личке | `journalctl --user -u telegram-agent -n 50`. Нет строки про чат — смотрите ленту (`tail`). Нет чата в `list_chats` — сообщение не дошло до аккаунта (писали не тому `@нику`). `rate limit` — лимиты. `rc≠0` — агент |
| Не отвечает в группе | Есть ли группа в папке (`get_folder`, спросить бота, строка `groups folder`)? Было ли обращение (reply, @, слово целиком)? Сообщения, отправленные до включения группы, не обрабатываются |
| Ответа нет, журнал пуст | Запуск идёт: большие задачи занимают минуты, строка появится в конце. Смотрите `pgrep` выше |
| «Не могу прочитать всё», «файл одной строкой» | Нужен запуск `tier=owner` (у гостей Read нет) и PostToolUse-хук в `settings.json`. После обновления Claude Code проверьте, что уведомление по-прежнему содержит `saved to /…txt` (регулярка в `reflow.py`) |
| Не запомнил | `cat memory.md`. Просьба должна быть от владельца. «Blocked by guard» на Edit — бот пытался писать не в тот путь |
| Сказал «готово», ничего не сделано | Проверьте реальное состояние. Промпт это запрещает; при повторе уточните формулировку в `prompt.md` |
| В ленте пусто | Лента стартует с первого входящего личного сообщения после запуска сервера. Проверьте `incoming_feed_status` и не вызывал ли кто-то `disable_incoming_feed` |
| `not authorized` | Сессию завершили в «Устройствах» или сменили пароль. Войдите заново ([INSTALL.md](INSTALL.md#4-войти-в-telegram-в-своём-терминале-не-через-ии)) |
| `AuthKeyDuplicatedError` | Где-то работает второй экземпляр с этой сессией |
| Клиент не видит инструменты | Сессия клиента запущена до установки — перезапустите. `curl … /mcp` возвращает `000` — сервер не работает |
| Файловые инструменты MCP отказывают | Путь вне `~/TelegramMCP` |
| Flood wait в журнале сервера | Telegram ограничивает частоту. Подождите или снизьте лимиты |
| Голосовые не расшифровываются | `systemctl --user status asr-server`, `curl …:5093/health`, журнал `asr-server`. Первое голосовое после простоя ждёт загрузки модели (~17 с), первое после установки — ещё и скачивания весов. Нужен `ffmpeg` |

## Обслуживание

**Обновление telegram-mcp:**

```bash
cd ~/.local/share/telegram-mcp
git fetch --tags && git tag --sort=-v:refname | head -3
git checkout vX.Y.Z && uv sync
systemctl --user restart telegram-mcp telegram-agent      # когда бот не занят
```

Перед обновлением прочитайте release notes. Пресет зависит от формата ответов:

- `wait_for_events`, `get_messages_after`, `list_folders`, `get_folder` — диспетчер;
- обёртки `{"result": "<JSON>"}` — `reflow.py`.

После обновления проверьте: в журнале нет `group poll error`, бот отвечает в личке и в группе.

**Обновление пресета:**

```bash
cd ~/Telegram-MCP-preset && git pull && ./install.sh
```

Если менялся `dispatcher.py`, затем перезапустите `telegram-agent`. Изменения шаблона `prompt.md`
сами не переносятся (ваш файл не перезаписывается). Сравните вручную:

```bash
diff ~/.local/share/telegram-agent/prompt.md agent/prompt.md
```

**Claude Code** обновляется сам. Если он разлогинится, ответы начнут падать с `rc≠0`.

**Ротация ленты** (сама не чистится):

```bash
systemctl --user stop telegram-agent
mv ~/.local/state/telegram-mcp/incoming_feed.jsonl{,.old}
systemctl --user start telegram-agent
```

**asr-server** обновляется вместе с пресетом (`install.sh`, версии зафиксированы в
`asr/uv.lock`). Затем `systemctl --user restart asr-server`.

**Бэкап** (хранить зашифрованно):

- `~/.local/share/telegram-mcp/.env` и `telegram_mcp_session.session`;
- `~/.local/share/telegram-agent/`: `config.env`, `prompt.md`, `memory.md`, `backend.env`.

Список групп хранится в самом Telegram (папка).

**Откат кода:** предыдущие версии лежат в `~/.local/share/telegram-agent/state/*.bak-*`.

## Голосовые сообщения

Голосовые и кружки расшифровываются **локально**: звук не покидает машину и ничего не стоит.

```
telegram-mcp (TELEGRAM_TRANSCRIBE_ENGINE=openai) ──HTTP──► asr-server 127.0.0.1:5093/v1 (onnx-asr)
```

- **Что такое asr-server.** Тонкая прослойка `asr/asr_server.py` над
  [onnx-asr](https://github.com/istupakov/onnx-asr) с OpenAI-совместимым
  `/v1/audio/transcriptions`:
  - ffmpeg декодирует любой формат;
  - записи длиннее 20 с режутся по паузам (Silero VAD), куски распознаются по очереди;
  - модель загружается при первом голосовом (~17 с) и выгружается после 10 минут простоя.
- **Модель по умолчанию:** GigaAM-v3 E2E RNN-T в полной точности (885 МБ). Русский, с
  пунктуацией и цифрами. На i7-8650U 74 с речи распознаются за ~8 с.
- **Почему эта модель.** Это лучшая модель GigaAM-v3 с пунктуацией (таблица авторов,
  [evaluation.md](https://github.com/salute-developers/GigaAM/blob/main/evaluation.md)):
  - средний WER по 10 русским наборам — 11.2 против 21.0 у Whisper large-v3;
  - F1 по запятым — 84.5, на уровне GigaChat Max Audio.
  
  Без пунктуации точнее по словам `gigaam-v3-rnnt` (WER 8.3), но текст выходит сплошной строкой.
- **Режим `TELEGRAM_TRANSCRIBE=auto`.** `get_history` и другие списки сами подставляют
  расшифровки, до 5 голосовых за вызов. В остальных случаях бот вызывает `transcribe_voice` сам
  (правило в `prompt.md`). Гостям инструмент тоже доступен, guard держит его в текущем чате.
- **Слова-обращения.** Диспетчер ищет `GROUP_TRIGGERS` только в тексте. Голосовое в группе
  считается обращением, если это reply на сообщение бота или в подписи есть @упоминание.

**Сменить модель.** Отредактируйте `ASR_MODEL` в `~/.config/systemd/user/asr-server.service` и
`TELEGRAM_TRANSCRIBE_OPENAI_MODEL` в `telegram-mcp.service` (он лишь для журнала), затем:

```bash
systemctl --user daemon-reload && systemctl --user restart asr-server
```

| `ASR_MODEL` | Что это |
|---|---|
| `gigaam-v3-e2e-rnnt` (по умолчанию), `gigaam-v3-e2e-ctc` | GigaAM-v3 с пунктуацией, русский |
| `gigaam-v3-rnnt`, `gigaam-v3-ctc` | GigaAM-v3 без пунктуации |
| `gigaam-multilingual-ctc`, `gigaam-multilingual-large-ctc` | GigaAM Multilingual, 70+ языков |
| `nemo-parakeet-tdt-0.6b-v3`, `nemo-canary-1b-v2` | NVIDIA, многоязычные (включая русский) |
| `nemo-fastconformer-ru-rnnt`, `t-tech/t-one`, `alphacep/vosk-model-ru` | другие русские модели |
| `onnx-community/whisper-large-v3-turbo` и т. п. | Whisper |
| `<user>/<repo>` | любая модель на HuggingFace в формате onnx-asr |

Полный список — в [документации onnx-asr](https://istupakov.github.io/onnx-asr/usage/#supported-model-names).

Другие переменные `asr-server`:

- `ASR_QUANTIZATION` — пусто (полная точность) или `int8`. На проверке GigaAM-v3 тексты почти
  совпали, int8 меньше в 4 раза (225 МБ) и в 1.4 раза быстрее — вариант для слабых машин;
- `ASR_THREADS` (4), `ASR_IDLE_UNLOAD` (600 с), `ASR_PORT` (5093);
- лимиты: `ASR_MAX_MB` (25 МБ на файл) и `ASR_MAX_SECONDS` (600 с; более длинная запись
  обрезается). Декодирование и распознавание идут по одному запросу за раз.

Гостям guard разрешает `transcribe_voice` только в текущем чате и только с локальным движком,
поэтому платный облачный движок они не вызовут, даже если ключ к нему появится.

**Подключить другой распознаватель.** Подойдёт любой OpenAI-совместимый (Speaches, облачный
Groq, OpenAI): поменяйте `TELEGRAM_TRANSCRIBE_OPENAI_URL`/`_MODEL` (ключ —
`TELEGRAM_TRANSCRIBE_OPENAI_API_KEY` в `.env`), остальное как в разделе upstream
[Voice transcription](https://github.com/chigwell/telegram-mcp#voice-transcription).

**Проверка и журнал:**

```bash
curl -s http://127.0.0.1:5093/health                      # "loaded": модель в памяти или нет
curl -s -F file=@voice.ogg http://127.0.0.1:5093/v1/audio/transcriptions
journalctl --user -u asr-server -f                        # "74.0s audio -> 525 chars in 5.8s"
```

Расшифровки кэшируются сервером telegram-mcp (SQLite, 600). Повторно одно и то же голосовое не
распознаётся.

## Стоимость

- Агент запускается только на обращение; фильтрация групп бесплатна.
- **Обычный ответ:** 3–9 шагов, 7–26 с, порядка $0.1–0.3 по ценам API (Sonnet).
- **Ответ в группе:** приходит через ~11 с (из них 5 с — ожидание тишины).
- **Большая задача владельца** (топик на 322 сообщения): 13 шагов, 85 с, около $0.5.
- Режим owner дороже: схем инструментов в нём в 9 раз больше.
- Любой reply на сообщение бота в группе (даже «АХАХА») — тоже обращение и короткий запуск.
