# Бэкенды автоответчика

Выберите `HARNESS` и `MODEL` в `~/.local/share/telegram-agent/config.env`. Уже установленные
пресеты без ключа `HARNESS` продолжат запускать Claude Code.

| `HARNESS` | Пример `MODEL` | Авторизация |
|---|---|---|
| `claude` | `claude-sonnet-5-5` | Вход в Claude Code или ключ в `backend.env` |
| `codex` | `gpt-6.2-sol` | `codex login` или `CODEX_API_KEY` |
| `opencode` | `opencode-go/qwen3.7-plus` | Вход через `/connect` в OpenCode v2.3.2 или более новой совместимой версии |
| `command` | Идентификатор, понятный вашему скрипту | Настраивается в вашем раннере |

Выберите модель из каталога своей учётной записи. Если бинарник установлен в другом месте,
задайте абсолютный путь через `CLAUDE_BIN`, `CODEX_BIN` или `OPENCODE_BIN`.

## Как применяются ограничения

`telegram-agent` определяет режим по ID отправителя. Для Codex, OpenCode и внешнего раннера он
поднимает на время запуска отдельный Streamable HTTP MCP на `127.0.0.1` со случайным URL.
Шлюз показывает гостю только инструменты текущего чата. Он проверяет аргументы каждого вызова.
Уведомления можно отправлять владельцу. Пересылка разрешена из текущего чата в чат уведомлений.
Память редактирует только владелец через `memory_read` и `memory_write`. Длинные текстовые
результаты читаются по частям через `read_result`. Частые инструменты владельца доступны напрямую.
Остальные доступны через `find_telegram_tool` и `call_telegram_tool`, чтобы весь каталог не загружался
в модель на каждый ответ.

Codex запускается с `--ephemeral`, read-only sandbox, без встроенных команд и пользовательского
конфига. Для отдельного входа задайте `CODEX_HOME` в `backend.env` и выполните `codex login`
с тем же значением в своём терминале. OpenCode запускается с приватным процессом и временным
конфигом, но использует базу авторизации OpenCode. Его сессии сохраняются как архивные. Учитывайте
это при выборе отдельной учётной записи или базы для службы.

Claude Code сохраняет свои хуки `guard.py` и `reflow.py` и выключенную auto-memory. В отличие от
этого режима, гостевым запускам через шлюз не передаётся файл памяти владельца. Встроенные
файловые инструменты Codex и OpenCode выключены. Файловые операции Telegram работают через
инструменты самого telegram-mcp в разрешённом сервером каталоге.

`RUN_TIMEOUT` и `OWNER_RUN_TIMEOUT` действуют для всех бэкендов. `MAX_TURNS` и
`OWNER_MAX_TURNS` задают предел шагов в Claude Code и OpenCode. Для Codex применяется таймаут.

По умолчанию OpenCode ждёт заголовки ответа модели до 20 секунд на попытку. Если раннер
завершился с таймаутом заголовков и ещё не пытался выполнить действие, автоответчик может
повторить запуск один раз со штатным лимитом OpenCode, в пределах оставшегося общего времени.
Штатное ожидание между фрагментами ответа сохраняется. При необходимости задайте
`OPENCODE_HEADER_TIMEOUT_MS` или `OPENCODE_CHUNK_TIMEOUT_MS` в миллисекундах в `config.env`.

## Веб-поиск в личке владельца

Для Codex, OpenCode и внешних раннеров добавьте `WEB_SEARCH=duckduckgo` в `config.env`.
Пишите обычным языком. Например, спросите «Какая последняя стабильная версия Python?»
или попросите «Сверь сроки поддержки Python 3.13 по официальным источникам». Бот сам решает,
нужны ли публичные источники. Команда `/web` перед темой сразу запускает поиск.

DuckDuckGo Lite получает поисковую фразу из свежего сообщения владельца. Укажите публичную тему
в сообщении. Для уточняющих вопросов с неявной темой назовите её ещё раз. Бот анализирует
фрагменты результатов и добавляет ссылки. После поиска он может отправить один текстовый
ответ в текущую личку.

Если конечный идентификатор в `MODEL` публичный, включите `WEB_SEARCH_PUBLIC_MODEL=1`.
Тогда бот сможет проверить и свою модель по просьбе «Сравни свою модель с GPT-6.2 Sol».
Для `MODEL=opencode-go/qwen3.8-flash` в поиск уйдёт только `qwen3.8-flash`. После смены
`MODEL` бот подставит новый идентификатор. Для частных имён моделей оставьте настройку выключенной.
Обычная просьба о сравнении позволяет сделать два отдельных запроса. Повтор успешного запроса
в рамках ответа возвращает уже полученные результаты и не расходует лимит.

Если агент дополнил запрос с названием и версией своими словами, шлюз может взять общее название
из исходного сообщения.
Отметка о прочтении и индикатор набора текста оставляют поиск доступным.

## Подключить другой агент

В `config.env` укажите, например:

```dotenv
HARNESS=command
MODEL=my-model
HARNESS_COMMAND=/home/user/.local/bin/my-telegram-runner
```

Диспетчер запускает указанную команду без оболочки, в пустом временном каталоге. В stdin приходит
UTF-8 промпт с задачей. Переменные `TG_MCP_URL`, `TG_MODEL` и `TG_MAX_TURNS` задают адрес шлюза,
модель и лимит шагов. Раннер должен подключить только этот MCP, отключить посторонние инструменты,
соблюдать лимит и вернуть ненулевой код при ошибке. Ответы собеседнику отправляются через
Telegram MCP. Проверяйте конфигурацию раннера на тестовом шлюзе, прежде чем использовать его с
установленной сессией Telegram.
